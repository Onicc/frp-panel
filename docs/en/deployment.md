# Deployment guide

## Components

| Component | Responsibility | Deployment method |
|---|---|---|
| Master | Web console, API, users, configuration, and node control connections | Docker Compose |
| Server | FRPS data entry that forwards public traffic to Clients | Embedded in the Master container as `default` |
| Client | `frp-panel-agent` and managed FRPC on a node | Installation command generated by the console |

The console displays a Client as a “Node.” The current release has no standalone Server runtime. Starting Master also starts the embedded Server, so a second container is not required.

## Deployment files

Keep the deployment in a dedicated directory:

```text
frp-panel/
├── compose.yaml
└── .env
```

### compose.yaml

Save the following complete file. Add every TCP or UDP proxy remote port to `ports` as needed.

```yaml
services:
  controller:
    image: ${FRP_PANEL_IMAGE:-onicc/frp-panel:edge}
    restart: unless-stopped
    environment:
      APP_GLOBAL_SECRET: ${APP_GLOBAL_SECRET:?set a random 32+ character secret}
      APP_COOKIE_SECURE: ${APP_COOKIE_SECURE:-true}
      APP_ENABLE_REGISTER: ${APP_ENABLE_REGISTER:-false}
      MASTER_API_HOST: ${PUBLIC_HOST:?set the public controller hostname}
      MASTER_API_SCHEME: ${MASTER_API_SCHEME:-https}
      MASTER_RPC_HOST: ${PUBLIC_HOST:?set the public controller hostname}
      CLIENT_API_URL: ${CLIENT_API_URL:?set the public API URL used by Agents}
      CLIENT_RPC_URL: ${CLIENT_RPC_URL:?set the public RPC URL used by Agents}
    ports:
      - "127.0.0.1:9000:9000"
      - "7000:7000"
      # Publish every TCP/UDP remote port used by a proxy, for example:
      # - "10000-10100:10000-10100/tcp"
      # - "10000-10100:10000-10100/udp"
    volumes:
      - frp-panel-data:/data
    healthcheck:
      test: ["CMD", "wget", "-qO-", "http://127.0.0.1:9000/api/v2/health"]
      interval: 30s
      timeout: 5s
      retries: 3

volumes:
  frp-panel-data:
```

### .env

Production example:

```dotenv
FRP_PANEL_IMAGE=onicc/frp-panel:edge

APP_GLOBAL_SECRET=REPLACE_ME
APP_COOKIE_SECURE=true
APP_ENABLE_REGISTER=true

PUBLIC_HOST=panel.example.com
MASTER_API_SCHEME=https
CLIENT_API_URL=https://panel.example.com
CLIENT_RPC_URL=wss://panel.example.com
```

Configuration notes:

- Replace `APP_GLOBAL_SECRET` with at least 32 random bytes and retain it securely.
- Set `APP_ENABLE_REGISTER=true` only while creating the initial Owner. Change it to `false` and reapply the Compose configuration immediately afterward.
- `PUBLIC_HOST` contains only the hostname, without a scheme or path.
- `CLIENT_API_URL` and `CLIENT_RPC_URL` are copied directly into Client installation commands and must be reachable from every node.
- Use same-origin `https://` and `wss://` endpoints in production. Do not use `localhost`, container names, `http://`, or `ws://`.
- `edge` rolls with `main`. Pin a tested `v*` image tag in stable environments.
- Restrict `.env` so only deployment administrators can read it.

See [configuration](/en/configuration) for optional settings.

## Networking and reverse proxy

Use a same-host HTTPS reverse proxy for public traffic and forward it to `127.0.0.1:9000`. This endpoint carries Web, API, and `wss` Agent RPC traffic.

| Port | Purpose | Exposure |
|---|---|---|
| `443/tcp` | HTTPS and WebSocket RPC | Public |
| `9000/tcp` | Master Web/API | Reverse proxy only |
| `7000/tcp` | Embedded FRPS | Open to Clients when using the default Server |
| Remote ports | TCP/UDP proxy traffic | Publish in Compose and allow in the firewall as needed |
| `9001/tcp` | Native gRPC RPC | No publishing required with the recommended WSS entry |
| `8999/tcp` | Embedded Server API | Never publish |

The panel hostname must resolve to the reverse proxy. The Master container must also be able to reach `CLIENT_API_URL` and `CLIENT_RPC_URL`.

If the reverse proxy is not on the Docker host, change the `127.0.0.1:9000:9000` binding and restrict access to the proxy with firewall rules.

## Server configuration

Master automatically creates and runs the `default` Server. After signing in, verify its status and configuration on the **Server** page.

Docker forwards only ports explicitly published in `compose.yaml`. Add a TCP or UDP proxy remote port to `ports` before using it; otherwise the console configuration can exist while public traffic cannot enter the container.

Standalone remote Servers are not supported by the current release. Creating a record on the Server page does not install or start FRPS on another machine.

## Client installation

Install every Client with a command generated by the console:

1. Sign in to Master and open **Nodes → Add node**.
2. Enter the node ID and create the enrollment.
3. Select Linux, macOS, or Windows.
4. Copy the complete displayed command and run it with administrator rights on the target node.
5. Return to Nodes and verify that the node is online.

The enrollment token is valid for ten minutes and becomes invalid after one successful use. Do not store or share installation commands containing the token.

If the command contains an incorrect hostname or scheme, first correct `CLIENT_API_URL` and `CLIENT_RPC_URL` in `.env`, reapply the Master configuration, and generate a new command.

See [Client / Agent installation and maintenance](/en/agent) for installation paths, service management, updates, and removal.

## Deployment checklist

- `https://panel.example.com/api/v2/health` is reachable.
- Public registration is disabled after creating the initial Owner.
- The `default` Server is online in the console.
- A Client installed with the console command is online.
- FRPS `7000` and all used remote ports are allowed by Compose, the host firewall, and the cloud security group.
- `.env` and the `frp-panel-data` volume are backed up; the data volume is not deleted during upgrades or service removal.

Review the [security baseline](/SECURITY) and [platform support matrix](/SUPPORT_MATRIX) before going live.
