# Deployment guide

## Understand Master, Server, and Client first

| Component | Responsibility | Current delivery model | Runs on |
|---|---|---|---|
| Master | Serves the Web console and HTTP API, manages users and configuration, and accepts node control connections | `onicc/frp-panel` image | Linux Docker host |
| Server | Runs FRPS, accepts public traffic, and forwards it to Clients | Embedded in the Master process as Server ID `default` | The same container as Master |
| Client | Runs `frp-panel-agent` and managed FRPC on a target node | One-time command generated by the Web console | Linux, macOS, or Windows node |

The console calls a **Client** a “Node.” The Agent is the operating-system service and FRPC is its managed data-plane process. Do not use the removed `frp-panel client` command.

The current v2 release has no independently runnable `server` subcommand or remote Server installer. The supported Server deployment is therefore the embedded `default` Server started by the Master Docker Compose service. Do not start a second controller container as a pretend standalone Server, and do not assume that creating a record on the Server page deploys FRPS remotely.

## Recommended topology and ports

Use one HTTPS hostname for both Web/API access and Agent RPC:

| External entry | Destination | Purpose | Required? |
|---|---|---|---|
| TCP `443` | Reverse proxy → `127.0.0.1:9000` | Web, API, and `wss` Agent RPC | Required in production |
| TCP `80` | Reverse proxy | ACME issuance or HTTPS redirect | Depends on certificate setup |
| TCP `7000` | Controller container | Embedded FRPS default bind port | Required with the default Server |
| Configured proxy remote ports | Controller container | Actual TCP/UDP tunnel traffic | As needed |
| TCP `9001` | Controller container | Native gRPC RPC | Does not need publishing with the recommended `wss` entry |
| TCP `8999` | Container only | Embedded Server API | Never publish it |

The panel hostname must resolve to the reverse proxy and the public address must also be reachable from the Controller container itself. This lets the embedded Server and external Clients use the same TLS-protected endpoints.

## Deploy Master and Server with Docker Compose

### 1. Prerequisites

- A Linux host with Docker Engine and the Docker Compose plugin.
- A hostname, such as `panel.example.com`, resolving to that host.
- A trusted HTTPS reverse proxy; the example below uses Caddy.
- Firewall rules that expose only the required ports in the table above.

Create a dedicated deployment directory and obtain the repository Compose file:

```bash
sudo install -d -m 0750 -o "$(id -u)" -g "$(id -g)" /opt/frp-panel
cd /opt/frp-panel
curl -fsSLo compose.yaml \
  https://raw.githubusercontent.com/Onicc/frp-panel/main/compose.yaml
```

### 2. Create the environment file

Generate a secret first:

```bash
openssl rand -hex 32
```

Put the result in `/opt/frp-panel/.env`. The file contains secrets and must use mode `0600`:

```dotenv
FRP_PANEL_IMAGE=onicc/frp-panel:edge
APP_GLOBAL_SECRET=REPLACE_ME
APP_COOKIE_SECURE=true
APP_ENABLE_REGISTER=true

PUBLIC_HOST=panel.example.com
MASTER_API_SCHEME=https
CLIENT_API_URL=https://panel.example.com
CLIENT_RPC_URL=wss://panel.example.com
```

`CLIENT_API_URL` and `CLIENT_RPC_URL` are copied directly into Client installation commands generated by the console. They must be public endpoints that a Client can actually reach. Never use `http://`, `ws://`, `localhost`, or a Docker service name in production.

Replace `REPLACE_ME` with the random output from the previous step. The application rejects this deliberately short placeholder and will not start with it.

```bash
chmod 0600 /opt/frp-panel/.env
```

`edge` rolls with `main`. Once an evaluated `v*` version is available, pin `FRP_PANEL_IMAGE` to it in production and back up the data before upgrading.

### 3. Configure the HTTPS reverse proxy

A minimal Caddy site follows. Caddy proxies WebSocket connections automatically:

```text
panel.example.com {
    encode zstd gzip
    reverse_proxy 127.0.0.1:9000
}
```

Start or reload the reverse proxy before starting frp-panel. If the proxy is on a different host, adjust the `127.0.0.1:9000:9000` binding in `compose.yaml` and use a firewall to allow only the reverse proxy to reach it.

### 4. Start and create the Owner

```bash
cd /opt/frp-panel
sudo docker compose config --quiet
sudo docker compose pull
sudo docker compose up -d
sudo docker compose ps
sudo docker compose logs --tail=100 controller
```

Open `https://panel.example.com` and create the only initial Owner. Immediately change `.env` to:

```dotenv
APP_ENABLE_REGISTER=false
```

Apply the change:

```bash
sudo docker compose up -d
```

Check health:

```bash
curl -fsS https://panel.example.com/api/v2/health
```

After signing in, open **Server**. The `default` entry should be online; it is the embedded FRPS running in the Master container.

### 5. Publish FRP proxy ports

Docker forwards only ports explicitly published in `compose.yaml`. Before creating a TCP or UDP proxy, add its remote port to `ports`, for example:

```yaml
ports:
  - "127.0.0.1:9000:9000"
  - "7000:7000/tcp"
  - "10000-10100:10000-10100/tcp"
  - "10000-10100:10000-10100/udp"
```

Run `docker compose up -d` after editing the file. Publish only the ports the service needs and mirror the restriction in the cloud security group and host firewall.

### 6. Back up and upgrade

SQLite data is stored at `/data` in the `frp-panel-data` Compose volume. Stop writes before copying the whole directory, and protect a separate copy of `.env`:

```bash
cd /opt/frp-panel
sudo docker compose stop controller
sudo mkdir -p backup
sudo docker compose cp controller:/data backup/
sudo docker compose start controller
```

To upgrade, change `FRP_PANEL_IMAGE`, then run:

```bash
sudo docker compose pull
sudo docker compose up -d
```

Do not run `docker compose down -v`; it deletes the database volume. Do not rotate `APP_GLOBAL_SECRET` during routine upgrades.

## Install a Client from the console

Do not hand-write commands containing node credentials, and do not run the repository bootstrap without its enrollment arguments. Use this flow:

1. Sign in to Master and open **Nodes → Add node**.
2. Enter a node ID containing only letters, digits, underscores, or hyphens and confirm.
3. Select the target **Linux**, **macOS**, or **Windows** tab.
4. Copy the complete generated command and run it with administrator rights on the target node.
5. Return to Nodes and verify that the node is online.

The enrollment token expires after ten minutes and is invalidated immediately after one successful redemption. The command contains that token; do not save it in scripts, shared shell history, tickets, or chat messages. If a command contains the wrong hostname or production-unsafe `http://` / `ws://` endpoints, correct Master's `CLIENT_API_URL` and `CLIENT_RPC_URL`, restart the container, and generate a new command.

The bootstrap selects the matching architecture, verifies the release against `checksums.txt`, installs into an OS-owned directory, and registers a service without leaving files in the current directory. See [Client / Agent installation and maintenance](/en/agent) for paths, maintenance, updates, and removal.

Use the native service manager to verify the installation:

::: code-group

```bash [Linux]
sudo systemctl status frp-panel-agent
sudo /usr/local/libexec/frp-panel/frp-panel-agent doctor --json
```

```bash [macOS]
sudo launchctl print system/io.github.onicc.frp-panel.agent
sudo /usr/local/libexec/frp-panel/frp-panel-agent doctor --json
```

```powershell [Windows PowerShell]
Get-Service frp-panel-agent
& "$env:ProgramFiles\frp-panel\frp-panel-agent.exe" doctor --json
```

:::

## Non-TLS localhost evaluation only

For a temporary evaluation where everything runs on the same machine, the reverse proxy can be omitted:

```dotenv
APP_COOKIE_SECURE=false
PUBLIC_HOST=127.0.0.1
MASTER_API_SCHEME=http
CLIENT_API_URL=http://127.0.0.1:9000
CLIENT_RPC_URL=ws://127.0.0.1:9000
```

Open `http://127.0.0.1:9000`. This configuration has no transport encryption. Never use it on the public Internet, on a shared LAN, in production, or for a Client installed on another machine.

See [configuration](/en/configuration), the [security baseline](/SECURITY), and the [platform support matrix](/SUPPORT_MATRIX) before going live.
