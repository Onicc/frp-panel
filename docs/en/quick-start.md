# Quick start

Master provides the control plane, Server is the default FRPS embedded in Master, and Client is the Agent plus managed FRPC installed on a Linux, macOS, or Windows node. The current release deploys Master and Server together with one Docker Compose service, then installs Clients from commands generated by the console.

## 1. Configure Master and Server

Copy the repository `compose.yaml`, generate at least 32 random bytes, and create `.env`:

```bash
openssl rand -hex 32
```

```dotenv
APP_GLOBAL_SECRET=REPLACE_ME
APP_COOKIE_SECURE=true
APP_ENABLE_REGISTER=true
PUBLIC_HOST=panel.example.com
MASTER_API_SCHEME=https
CLIENT_API_URL=https://panel.example.com
CLIENT_RPC_URL=wss://panel.example.com
```

Replace `REPLACE_ME` with the random value generated above.

Point an HTTPS reverse proxy at `127.0.0.1:9000`, then start the stack:

```bash
docker compose config --quiet
docker compose pull
docker compose up -d
```

Enable registration only while creating the one initial Owner. Set `APP_ENABLE_REGISTER=false` afterward and run `docker compose up -d` again. Embedded FRPS uses `7000`; every proxy remote port must also be published by Compose.

## 2. Install a Client

Open **Nodes → Add node**, enter a name, and create a one-time command valid for ten minutes. Select Linux, macOS, or Windows and run it on that node. Redemption permanently invalidates the token.

## 3. Check it

Verify that the `default` Server and new node are online in the console, then inspect `frp-panel-agent` with the native service manager. See [Client / Agent installation and maintenance](/en/agent) for exact commands.

See the [deployment guide](/en/deployment) for production reverse proxy, port, backup, and upgrade steps. Read [configuration](/en/configuration) and the [security baseline](/SECURITY) before going live.
